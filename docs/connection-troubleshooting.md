# Database connection hurdles

Start with **Test Connection**. Distinguish the SSH login from the database login: they can use different hosts, users and credentials.

| Situation                                  | What is needed                                                            | Current extension behavior                                                                                                                                                                                                                              |
| ------------------------------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VPS database on localhost                  | SSH access and TCP forwarding; database reachable from the SSH host       | Built-in key/agent tunnel. Database Host/Port are interpreted on the server side.                                                                                                                                                                       |
| Database in Docker                         | A port reachable from the SSH host, often published to VPS loopback       | A container's localhost is not the VPS's localhost. Supply the published address/port.                                                                                                                                                                  |
| Firewall/IP allowlist/private network      | Reachable SSH host, VPN, provider allowlist or private-network access     | SSH helps only if the SSH server can reach the database; it cannot bypass provider access controls.                                                                                                                                                     |
| Custom CA or certificate hostname mismatch | Correct database hostname and trusted certificate authority               | SQL CA input is supported. SSH preserves the database TLS identity; it does not automatically make a wrong certificate valid. Custom NoSQL CAs are not exposed.                                                                                         |
| Client certificates or Oracle wallets      | Provider-specific client certificate/key or wallet setup                  | Not exposed by the form. Oracle currently supports password authentication in Thin mode and a CA certificate for TLS.                                                                                                                                   |
| AWS IAM, Azure Entra or SSO                | Provider login, roles and possibly token generation/refresh               | Automatic cloud identity login/refresh and integrated Windows/Kerberos authentication are not implemented. A token may work as a manually supplied password where the specific driver/provider supports it; this is not an automatic login integration. |
| MongoDB replica sets/SRV                   | Access to all discovered members, suitable DNS and topology-aware routing | SSH requires a direct member URL with discovery disabled. Use a VPN/Remote SSH for discovered deployments.                                                                                                                                              |
| Redis Cluster/Sentinel                     | Discovery and routing to the advertised nodes                             | Standalone Redis is supported; cluster/Sentinel mode is not implemented.                                                                                                                                                                                |
| SQL Server named instances                 | Explicit reachable TCP port, preferably static                            | Enter host and port rather than an instance-name discovery expression.                                                                                                                                                                                  |
| Oracle connection identity                 | Correct service name and privileges                                       | The Database field is the service name; SID aliases, wallet configuration and Thick mode are not configured.                                                                                                                                            |
| Transaction poolers                        | Session persistence for temporary tables and transaction state            | Neon preset uses direct endpoints; Supabase preset accepts direct/session pooling and rejects standard transaction-pooler port 6543.                                                                                                                    |
| Remote SSH/WSL/container workspace         | Keys, agent and network access on the extension host                      | File paths and localhost refer to that environment, not necessarily the desktop.                                                                                                                                                                        |
| SSH bastion with MFA/multiple jumps        | Interactive authentication or hop chaining                                | One key/agent-authenticated hop is supported. SSH passwords, keyboard-interactive MFA, ProxyJump and OpenSSH config aliases are not implemented.                                                                                                        |

A failed SSH key unlock is different from a rejected database password. A changed host fingerprint must be verified independently; use **Forget SSH Host Key** only for a legitimate rotation. Avoid repeatedly rerunning writes after a disconnect until you have checked whether the database applied them.

Sources: [MongoDB direct-member connections and SSH](https://www.mongodb.com/docs/languages/python/pymongo-driver/current/connect/connection-targets/), [Redis cluster redirects](https://redis.io/docs/latest/operate/oss_and_stack/reference/cluster-spec/), [SQL Server TCP port configuration](https://learn.microsoft.com/en-us/troubleshoot/sql/database-engine/connect/network-related-or-instance-specific-error-occurred-while-establishing-connection), [AWS IAM database authentication](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/UsingWithRDS.IAMDBAuth.Connecting.html).

## libSQL and Turso

Choose the adapter matching the database engine: libSQL for legacy/libSQL endpoints, Turso for the newer Turso engine. Use the database URL and a **database token**, not a provider management API key. `libsql://` selects verified HTTPS; supply no token/query options in the URL. Expired/revoked tokens need **Change Database Credentials**. Local `file:` databases, custom CAs, client certificates, remote encryption keys, replicas/sync and built-in SSH are not supported by these adapters in this release. Plain HTTP is explicit and intended for local/self-hosted development. Remote SSH can run the extension host beside a private endpoint. Staged grid edits require a writable connection and a complete primary key. Review SQL, then commit and confirm. Commit or roll back any open SQL transaction first; these adapters cannot isolate a nested grid batch with savepoints. Writes use the token's database permissions.
